# Murmur 自定义桌宠导入与动画生成设计

## 目标

用户上传自己的桌宠图片后，可以先得到透明背景的静态桌宠；如果用户已有 GIF、动图或序列帧，可以进一步生成可播放的桌宠动画。只上传单张图片时，AI 动作生成作为后续可选能力，不阻塞基础导入流程。

## 分阶段方案

### V1：本地抠图与动画导入

- 上传单张图片后，使用 macOS 本地前景分割生成透明 PNG。
- 在保存前提供原图、抠图结果和边缘修正预览；抠图失败时允许保留原图或重新选择。
- 支持导入 GIF、APNG 和 2 至 24 张序列帧。
- 导入后自动拆帧、裁切透明边缘、统一画布、固定主体锚点并生成预览。
- 用户确认预览后才替换当前桌宠；取消操作不会修改已保存设置。
- 处理过程全部在本机完成，不上传用户图片，也不产生调用费用。

### V2：可选 AI 动作生成

- 在静态抠图完成后提供“生成动作”入口，不与普通上传按钮绑定。
- 用户选择动作模板，例如呼吸、打招呼、玩耍或睡觉，再明确确认上传图片。
- 云端生成服务返回候选动画，客户端继续执行抠图、逐帧对齐、尺寸标准化和循环检测。
- 生成结果必须先预览；身份漂移、额外肢体、背景残留或循环跳变时允许重新生成或放弃。
- 界面明确显示预计等待时间、次数或费用，以及图片会被发送到云端。

## 数据流

静态图片导入流程：选择图片 → 本地抠图 → 边缘预览 → 保存透明 PNG → 显示静态桌宠。

已有动画导入流程：选择动图或多帧图片 → 拆帧 → 主体锚点对齐 → 循环预览 → 保存帧序列 → 播放动画。

AI 生成流程：透明静态图 → 选择动作 → 用户确认云端处理 → 生成候选 → 本地清理与对齐 → 预览确认 → 保存帧序列。

## 存储与兼容

- 每个自定义桌宠使用独立目录，保存原图、透明静态图、帧序列和配置文件。
- 配置记录帧顺序、帧间隔、循环方式、静止帧、锚点和生成来源。
- 没有动画或动画文件损坏时，自动回退到透明静态图。
- 删除桌宠时只删除对应目录，不影响内置小猫和其他自定义桌宠。

## 验收标准

- 普通图片可以在本地完成抠图、预览、确认和取消。
- GIF 或序列帧导入后不会串帧，主体不会因装饰元素左右跳动。
- 保存前的任何操作都不会直接覆盖当前桌宠。
- AI 不可用、超时或生成失败时，静态桌宠仍可正常使用。
- 未经用户明确确认，不向云端发送图片。
